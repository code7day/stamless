# Genesis CMS — API v1 (Headless)

> Versión: v1 · Última actualización: 2026-08-17 · Ver también: [`docs/api/openapi.v1.yaml`](./openapi.v1.yaml)

## Introducción

La API v1 de Genesis CMS expone, en modo **solo lectura** (salvo el envío de formularios), el contenido publicado de un tenant para que un frontend headless (Astro, Next.js, o cualquier cliente HTTP) lo consuma. Actualmente opera en un único idioma (`lang_iso = es`) y expone únicamente contenido publicado/activo — nunca borradores.

Toda la API requiere autenticación por **token Bearer** (Laravel Sanctum). No hay endpoints públicos sin token.

## Base URL

Genesis CMS responde en varios dominios según el rol. El dominio de la API es **`APP_URL_API`** — no confundir con `APP_URL` (que es el de la landing) ni con `APP_URL_CONSOLE` (el panel admin).

```
{APP_URL_API}/v1/{tenant_slug}/...
```

Por ejemplo, contra CICA360: `https://api.stamless.host/v1/cica360/pages`.

## Autenticación

Todas las rutas de `/v1/{tenant_slug}/*` exigen el header:

```
Authorization: Bearer {token}
```

El token es un **personal access token de Sanctum**, generado desde Console (ver más abajo). Cada token tiene un tenant dueño (el tenant del usuario que lo creó) y una o más **abilities**:

| Ability | Para qué sirve |
|---|---|
| `content:read` | Todos los endpoints `GET` (pages, posts, menus, sliders, media) |
| `forms:submit` | `POST forms/{slug}/submit` |

Reglas de autorización, en orden:

1. **Sin header `Authorization`** → `401`.
2. **Token inválido, malformado o revocado** → `401`.
3. **Token válido pero sin la ability requerida por el endpoint** → `403`.
4. **Token válido pero de un tenant distinto al `{tenant_slug}` del path** → `403` (nunca se filtra si el tenant del path existe o no).
5. **`{tenant_slug}` no existe o está inactivo** → `404` (mismo mensaje genérico para ambos casos, para no revelar cuál de las dos razones aplica).

### Cómo crear un token (Console)

1. Iniciá sesión en Console (`studio.stamless.host`) con tu usuario del tenant.
2. Andá a **Desarrolladores → API Tokens**.
3. **Crear token**: ponele un nombre descriptivo (ej. `frontend-produccion`), elegí las abilities que necesita y una expiración (`Nunca`, `1 día`, `30/90 días`, `1 año`). Pasada esa fecha el token deja de funcionar solo (`401`), sin que haga falta revocarlo a mano.
4. El token en texto plano se muestra **una sola vez**, en un banner de advertencia. Copialo antes de cerrar ese banner — Sanctum solo guarda el hash, así que si lo perdés no hay forma de recuperarlo (hay que revocar y crear uno nuevo).
5. El listado siempre muestra el token enmascarado (`••••••••` + últimos 4 caracteres) y su expiración, nunca el valor completo.

### Cómo revocar un token

En **API Tokens**, botón **Revocar** en la fila del token. Es inmediato: cualquier request posterior con ese token responde `401`.

## Envelope de response

Toda respuesta (éxito o error) sigue el mismo formato. Las claves con valor vacío/nulo **se omiten** (no se envían como `"key": null`), así que no todas las respuestas tienen exactamente las mismas claves.

```jsonc
{
  "success": true,       // boolean, siempre presente
  "message": "...",      // string, solo si hay un mensaje relevante
  "status_code": 200,    // int, siempre presente
  "data": { ... },       // el recurso o colección — solo en éxito
  "meta": { ... },       // paginación — solo en listados
  "links": { ... },      // links de paginación — solo en listados
  "errors": { ... }      // detalle de error — solo en 4xx/5xx con detalle estructurado
}
```

Listados paginados (`GET pages`, `GET posts`) agregan:

```jsonc
"meta": {
  "current_page": 1,
  "per_page": 15,
  "total": 42,
  "last_page": 3
},
"links": {
  "first": "https://.../pages?page=1",
  "prev": null,
  "next": "https://.../pages?page=2",
  "last": "https://.../pages?page=3"
}
```

`per_page` acepta `?per_page=N` en la query string (máximo 50, default 15).

## Errores

| Código | Cuándo | `errors.code` | Ejemplo |
|---|---|---|---|
| `401` | Sin header `Authorization` | `unauthenticated` | `{"success": false, "message": "No autenticado. Enviá un token Bearer en Authorization.", "status_code": 401, "errors": {"code": "unauthenticated"}}` |
| `401` | Token inválido, malformado, expirado o revocado | `token_invalid` | `{"success": false, "message": "Token inválido o expirado.", "status_code": 401, "errors": {"code": "token_invalid"}}` |
| `403` | Token sin la ability requerida, o de otro tenant | `forbidden` | `{"success": false, "message": "No tenés permiso para este recurso.", "status_code": 403, "errors": {"code": "forbidden"}}` |
| `404` | Tenant/página/post/menú/slider/media no encontrado (o tenant inactivo) | `not_found` | `{"success": false, "message": "Página no encontrada.", "status_code": 404, "errors": {"code": "not_found"}}` |
| `422` | Validación (ej. `forms/submit` con campos requeridos faltantes) | `validation` | `{"success": false, "message": "Revisá los datos enviados.", "status_code": 422, "errors": {"code": "validation", "fields": {"message": ["El campo message es obligatorio."]}}}` |
| `429` | Rate limit superado | `too_many_requests` | `{"success": false, "message": "Demasiadas solicitudes. Intentá más tarde.", "status_code": 429, "errors": {"code": "too_many_requests"}}` |

`errors.code` es estable y pensado para lógica de cliente (`switch` sobre el código) — el `message` es para mostrarlo tal cual a una persona, puede cambiar de texto sin previo aviso.

**Rate limiting**: 60 requests/minuto por IP en todos los endpoints de lectura; 10 requests/minuto por IP adicionales en `forms/{slug}/submit`.

## Multi-tenant

Cada request va scopeada por el segmento `{tenant_slug}` del path (ej. `cica360`), y se valida que el token pertenezca a ese mismo tenant. No existe forma de leer contenido de un tenant con el token de otro.

## Idioma (`lang_iso`)

Todos los endpoints devuelven contenido en `lang_iso = es` — no hay selector de idioma todavía. Si en el futuro se agrega soporte multi-idioma, será vía un segmento de path o un header dedicado.

## Endpoints

### `GET /pages`

Lista páginas publicadas, paginada.

- **Abilities**: `content:read`
- **Query params**: `type` (`page`|`landing`|`header`|`footer`|`legal`), `is_home` (`0`|`1`), `per_page` (1–50)

**Response `200`** (resumida — sin `blocks`/`meta`/`links`/`properties`, para listados livianos):

```json
{
  "success": true,
  "status_code": 200,
  "data": [
    {
      "uuid": "0199a1c2-...",
      "slug": "home",
      "type": "page",
      "is_home": true,
      "pretitle": null,
      "title": "Home",
      "subtitle": null,
      "published_at": "2026-08-16T00:00:00.000000Z"
    }
  ],
  "meta": { "current_page": 1, "per_page": 15, "total": 5, "last_page": 1 },
  "links": { "first": "...", "prev": null, "next": null, "last": "..." }
}
```

### `GET /pages/{slug}`

Detalle completo de una página publicada, con sus `blocks` visibles y ordenados.

- **Abilities**: `content:read`
- **Response `404`** si no existe, no está publicada, o pertenece a otro tenant.

```json
{
  "success": true,
  "status_code": 200,
  "data": {
    "uuid": "0199a1c2-...",
    "slug": "home",
    "type": "page",
    "is_home": true,
    "pretitle": null,
    "title": "Home",
    "subtitle": null,
    "meta": {
      "seo_title": "CICA360 — Seguros, finanzas y asesoría legal",
      "seo_description": "Integramos seguros, finanzas y asesoría legal para potenciar tu crecimiento."
    },
    "links": [],
    "properties": {},
    "published_at": "2026-08-16T00:00:00.000000Z",
    "blocks": [
      {
        "uuid": "0199a1c3-...",
        "type": "hero",
        "pretitle": null,
        "title": null,
        "subtitle": null,
        "content": { "mode": "slider", "slider_slug": "home" },
        "links": [],
        "properties": {},
        "sort_order": 0
      },
      {
        "uuid": "0199a1c4-...",
        "type": "cta",
        "pretitle": null,
        "title": "¿Listo para transformar tu negocio?",
        "subtitle": "Conversemos y descubre cómo podemos ayudarte",
        "content": { "body": "Agendá una primera conversación sin costo con nuestro equipo de asesores." },
        "links": [
          {
            "type": "primary",
            "label": "Empezar a planificar",
            "source_type": "page",
            "source_slug": "contacto",
            "href": "/contacto",
            "target": "_self"
          }
        ],
        "properties": {},
        "sort_order": 6
      }
    ]
  }
}
```

Notar: `content.slider_slug` (no `slider_id`), `links[].source_slug`/`links[].href` (no `source_id`), `properties`/`content` vacíos siempre como `{}`.

Esta resolución de ids internos a datos públicos aplica a **todos** los campos `*_id` de `content`, no solo al hero, sin importar cuántos haya por bloque (todo batcheado, sin N+1):

| Bloque | Campo interno (DB) | Campo público (API) |
|---|---|---|
| `hero` (modo `slider`) | `content.slider_id` | `content.slider_slug` |
| `hero` (modo `manual`) | `content.background_image_id` / `_tablet_id` / `_mobile_id` | `content.background_image` / `_tablet` / `_mobile` (objeto Media o `null`) |
| `heading` | `content.image_desktop_id` / `_tablet_id` / `_mobile_id` | `content.image_desktop` / `_tablet` / `_mobile` (objeto Media o `null`) |
| `image`, `split` | `content.media_id` | `content.media` (objeto Media o `null`) |
| `features` | `content.items[].image_id` | `content.items[].image` (objeto Media o `null`) |
| `testimonials` | `content.items[].avatar_id` | `content.items[].avatar` (objeto Media o `null`) |
| `logos` | `content.items[].media_id` | `content.items[].media` (objeto Media o `null`) |
| `services_grid` | `content.items[].image_id` | `content.items[].image` (objeto Media o `null`) |
| `services_grid` | `content.items[].page_id` | `content.items[].page_slug` + `content.items[].href` |

Ejemplo de un item de `services_grid` ya resuelto:

```json
{
  "title": "Seguros generales",
  "subtitle": "Cobertura patrimonial y de responsabilidad civil a medida.",
  "image": null,
  "page_slug": "servicios",
  "href": "/servicios",
  "url": null,
  "badge": null
}
```

### `GET /menus/{slug}`

Menú con sus items activos, en árbol (`children` anidados hasta un nivel).

- **Abilities**: `content:read`
- **Response `404`** si no existe.

```json
{
  "success": true,
  "status_code": 200,
  "data": {
    "uuid": "0199a3a1-...",
    "name": "Menú principal",
    "slug": "menu-principal",
    "items": [
      { "uuid": "0199a3a2-...", "title": "Home", "type": "page", "href": "/", "target": "_self", "sort_order": 0, "children": [] },
      { "uuid": "0199a3a3-...", "title": "Servicios", "type": "page", "href": "/servicios", "target": "_self", "sort_order": 2, "children": [] },
      { "uuid": "0199a3a4-...", "title": "Consultar ahora", "type": "page", "href": "/contacto", "target": "_self", "sort_order": 4, "children": [] }
    ]
  }
}
```

`href` viene resuelto por el backend (`/` para la home, `/{slug}` para pages, `/blog/{slug}` para posts, o la URL cruda para items `external`/`custom`) — nunca hay que reconstruirlo en el frontend.

### `GET /media/{uuid}`

Un archivo de media por `uuid` (identificador público — nunca el `id` interno).

- **Abilities**: `content:read`

```json

  "status_code": 200,

```

### `POST /forms/{slug}/submit`

Envía un formulario público (ej. contacto). Nunca expone datos sensibles en la respuesta.

- **Abilities**: `forms:submit`
- **Rate limit**: 10/min por IP (además del límite general de 60/min)

**Request**:

```json
{
  "name": "Juan Pérez",
  "email": "juan@example.com",
  "phone": "099123456",
  "message": "Quiero más información sobre seguros de vida."
}
```

**Response `201`**:

```json
{
  "success": true,
  "message": "Formulario enviado correctamente.",
  "status_code": 201,
  "data": { "uuid": "0199a6d1-..." }
}
```

**Response `422`** (campo requerido faltante):

```json
{
  "success": false,
  "message": "Revisá los datos enviados.",
  "status_code": 422,
  "errors": { "code": "validation", "fields": { "message": ["El campo message es obligatorio."] } }
}
```

## Buenas prácticas

- Guardá el token en una variable de entorno del build del frontend (ej. `PUBLIC_API_TOKEN` en Astro), nunca lo commitees.
- Un token por frontend/entorno (`frontend-produccion`, `frontend-staging`) — así podés revocar uno sin afectar al otro.
- Cacheá agresivamente en el frontend: el contenido es publicado/estático, no cambia por request.
- Usá `per_page` chico en listados si solo necesitás los primeros N items — evita traer de más.
- Los links siempre traen `href` resuelto — no reconstruyas rutas a mano a partir de `source_slug` salvo que necesites lógica de ruteo específica del frontend.

## Ejemplos

### cURL

```bash
curl -s \
  -H "Authorization: Bearer TU_TOKEN" \
  -H "Accept: application/json" \
  "https://api.stamless.host/v1/cica360/pages/home"
```

```bash
curl -s -X POST \
  -H "Authorization: Bearer TU_TOKEN" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"name":"Juan Pérez","email":"juan@example.com","message":"Hola"}' \
  "https://api.stamless.host/v1/cica360/forms/contacto/submit"
```

### fetch (JS/TS)

```ts
const API_BASE = "https://api.stamless.host/v1/cica360";
const API_TOKEN = import.meta.env.PUBLIC_API_TOKEN;

async function getPage(slug: string) {
  const res = await fetch(`${API_BASE}/pages/${slug}`, {
    headers: {
      Authorization: `Bearer ${API_TOKEN}`,
      Accept: "application/json",
    },
  });

  const { success, data, message } = await res.json();

  if (!success) {
    throw new Error(message ?? `Error ${res.status}`);
  }

  return data;
}
```

## Limitaciones actuales

- No hay rotación automática de tokens ni notificación antes de que expiren — el frontend tiene que manejar un `401` por expiración igual que uno por revocación manual (mismo código, mismo mensaje "Token inválido o expirado.").
- El campo `Content-Type` de `Media.mime_type` viene tal cual se cargó el archivo — no hay validación/normalización adicional en la API.
- Los campos `image`/`avatar`/`media`/`background_image*` devuelven `null` hasta que se cargue el archivo correspondiente para ese contenido.
